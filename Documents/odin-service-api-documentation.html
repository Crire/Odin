Odin Service API / Notification Worker

A Service API e o servico interno em Go responsavel por processar notificacoes e tarefas assincronas do Odin. Ela nao contem regras complexas de kanban; essas regras pertencem a General API.

Stack

  • Go 1.26.
  • net/http e chi para HTTP interno.
  • PostgreSQL via pgx.
  • Redis via go-redis para locks, idempotencia e throttle.
  • RabbitMQ via amqp091-go como gatilho opcional.
  • slog para logs estruturados.
  • Provedor noop por padrao e FCM opcional.

Responsabilidades

  • Buscar notification_jobs pendentes e vencidos.
  • Fazer claim atomico dos jobs com PostgreSQL.
  • Evitar processamento duplicado com Redis.
  • Aplicar throttle por usuario.
  • Verificar se a task ainda esta ativa e se o usuario ainda e responsavel/criador.
  • Verificar janela de notificacao do usuario.
  • Buscar devices ativos.
  • Enviar notificacoes pelo provedor configurado.
  • Registrar notification_deliveries.
  • Marcar jobs como SENT, FAILED, SKIPPED ou reprogramar retry.

Endpoints internos

GET  /internal/v1/health
GET  /internal/v1/ready
POST /internal/v1/notification-jobs/process
POST /internal/v1/notification-jobs/{jobId}/retry

Endpoints de acao exigem X-Service-Token ou Authorization: Bearer <token>.

Fluxo de processamento

  1. O scheduler chama ProcessDue periodicamente.
  2. O repositorio faz claim atomico de jobs PENDING vencidos.
  3. O Redis cria lock por job e marca idempotency_key.
  4. O worker valida task, janela de horario e throttle.
  5. O worker envia para cada device ativo.
  6. O worker grava uma entrega por device.
  7. Se houver sucesso, o job vira SENT; se todos falharem, entra em retry ou FAILED.
